# Releasing

This repository publishes all three Kotlin Multiplatform modules to Maven
Central. The `Release` workflow can also publish the existing `@zenwave360/dsl`
npm package generated by `dsl-kotlin`.

## Maven artifacts

Each module publishes its Kotlin Multiplatform metadata artifact and JVM and JS
variants under the shared group and version:

| Module | Coordinates |
| --- | --- |
| `dsl-kotlin` | `io.zenwave360.dsl:dsl-kotlin`, `dsl-kotlin-jvm`, `dsl-kotlin-js` |
| `dsl-views` | `io.zenwave360.dsl:dsl-views`, `dsl-views-jvm`, `dsl-views-js` |
| `dsl-docs` | `io.zenwave360.dsl:dsl-docs`, `dsl-docs-jvm`, `dsl-docs-js` |

The variant artifacts share the same version as their module's metadata
artifact. `dsl-views` depends on `dsl-kotlin`; `dsl-docs` depends on
`dsl-views`.

## Release steps

1. Add `release-notes/release-notes.v<VERSION>.md` and commit the notes and
   intended release changes to `main`.
2. Run the **Release** workflow from `main` with the semantic `version` (no
   `v` prefix). `developmentVersion` is optional; otherwise the workflow uses
   the next patch `-SNAPSHOT`. Enable `publishNpm` only when publishing
   `@zenwave360/dsl` is intended and npm trusted publishing is configured.
3. The shared release workflow prepares the version change and tag, then runs
   the root Gradle build and Maven publication. Root `build` and
   `publishToMavenCentral` include all three modules.
4. Review the Maven deployment or deployments in the Sonatype Central Portal
   and publish them there. The deployment includes artifacts that depend on
   one another, so publish the complete set for the release.
5. If npm publication was enabled, approve the `npm-publish` environment. The
   workflow publishes only the `dsl-kotlin` generated package,
   `@zenwave360/dsl`.

## Snapshot publishing

`Build and Publish Snapshots` runs on pushes to `develop` and `next`. Keep the
root version in `build.gradle.kts` on a `-SNAPSHOT` suffix. The root Gradle
publishing task publishes all three modules. The optional npm snapshot job
continues to publish only `@zenwave360/dsl` from
`build/js/packages/dsl-kotlin`.

## GitHub and publishing setup

Configure the GitHub environments and secrets required by the shared release
workflow in the repository. Maven publication requires the Central Portal
credentials and signing key secrets used by the workflow. npm publication also
requires the `npm-publish` environment and a trusted publisher for the
`release.yml` workflow; snapshot npm publication requires the corresponding
snapshot environment and trusted publisher. The initial npm package
publication must be completed manually before npm trusted publishing can be
used.

The release and snapshot workflows call reusable workflows in
`ZenWave360/release-workflows`. Review those workflow revisions and their
environment requirements before relying on changes to the shared workflows.
